# discord.zig status

This package implements a dependency-light Discord bot core in Zig. It is designed around small public modules, injectable transports, and testable protocol helpers rather than a monolithic runtime.

The REST client and gateway have been verified live against the real Discord API: a bot authenticates over HTTPS, reads (`GET /users/@me`, `/gateway/bot`, `/applications/@me`, `/users/@me/guilds`, guild channels), writes (bulk-overwrite global slash commands + read back + clear), sends a plain message and a multipart file upload, deletes both, and completes a real gateway connect → IDENTIFY → READY. The `examples/e2e_check.zig` harness reproduces all of this (token supplied at build time via `-Ddiscord_token=...`, never committed).

## Remaining work

- Deeper runtime integrations for platform-specific shutdown hooks.
- Voice audio codec (Opus encode/decode) and the UDP socket loop: the RTP framing and packet encryption are provided, but Opus needs an external native lib (as in Discord.js).
- Full multi-process shard orchestration and supervision.
- Broader model coverage for the full Discord API surface.
- Broader model coverage for lower-priority Discord API resources.

## Verification

The package is intended to pass:

```sh
zig build test
zig build
```

The `ping_bot` example uses an in-memory REST transport, so it does not need a Discord token. The `slash_bot` example is an offline slash-command cookbook (command definition + validation, interaction router dispatch to a typed handler, ephemeral reply, and a colored embed). Both build via `zig build` and run standalone.
